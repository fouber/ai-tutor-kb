# 知识点设计细则

库的质量 = 出题的质量上限。这份细则解决「知识点该拆多细、definition 该写什么」。

## 粒度：一个点 = 一次可独立考察的最小单元

判断标准：能不能只针对这一个点出一道题，而不牵连别的点。

- ❌ 太粗：`100以内的加减法`——这是一个单元，不是一个点，出题引擎只能泛泛出题。
- ❌ 太细：`23-8 的计算`——这是一道题，不是一个点，会导致重复出同一道题。
- ✅ 合适：`两位数减一位数（需退位）的竖式计算`——范围明确，能出无数道同构题。

一个 300 点的库几乎总是拆得太细或塞了多个主题；专项库 20–60 点、同步单元库 30–100 点是常态。

## definition：写给出题引擎看，不是写给孩子看

definition 会原文喂给出题引擎。除了「是什么」，更值钱的是「哪里会错」：

```
term: 两位数减法中的退位判断
definition: 个位不够减时需要向十位借 1（退位），个位按「加 10 再减」计算，十位记得减去借走的 1。
易错点：① 忘记十位减 1（如 52-38 算成 24）；② 个位够减却误退位；
③ 连续退位时（如 100-56）十位为 0 需继续向百位借。
出题时应混入「不需要退位」的题目，考察判断而非机械退位。
```

最后那句「出题时应……」是**给引擎的导演指令**，非常有效，鼓励使用。

支持 Markdown 与 LaTeX 公式（`$...$`）。

## 章节铺法

章节是难度台阶，不是目录复印。专项库的经典铺法：

1. 前置热身（确认地基，1 章）
2. 核心能力，按认知步骤拆开（2–4 章，一章一个步骤）
3. 混合与应用（1–2 章，把步骤组合进真实情境）

同步库可以贴教材目录，但每章内部知识点仍按上面的粒度标准重写，不要照抄课本标题。

## 库名语法「锚点 · 范围 · 定位」

| 段 | 作用 | 例 |
|---|---|---|
| 锚点 | 教材版本+年级，钉住语境 | 人教二下 / 北师大五上 / 新概念一册 |
| 范围 | 练什么，一眼可读 | 100以内退位减法 / 现在完成时 |
| 定位 | 专项突破 / 同步练习 / 拔高 | 专项突破 |

好库名本身就是一句合格的需求描述。写不出三段齐全的库名，通常说明澄清还没做完——回去补问。
